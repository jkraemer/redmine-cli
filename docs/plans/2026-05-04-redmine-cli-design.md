# Redmine/Planio Go CLI — Phase 1 Design

**Ticket:** Redmine #1459
**Date:** 2026-05-04
**Scope:** Phase 1 only (read operations); minimal viable executable
**Author:** Forge

## Problem Statement

Build a Go-based CLI tool for the Redmine/Planio API, distributed as a single
static binary. Models on the Basecamp CLI agent-accessible pattern: shell
commands over MCP, context-efficient, agent-native UX. This first iteration
covers Phase 1 (read operations) only.

## Why CLI over MCP

- **Attachment handling**: a CLI can download to a temp file and return a path,
  avoiding base64 over a protocol boundary.
- **Context-window cost**: MCP injects schemas every turn; a CLI costs tokens
  only when invoked.
- **Distribution**: single static binary, no runtime deps.

## Goals

A working `redmine-cli` binary covering:

- `issues list`
- `issues get <id>`
- `attachments download <id>`
- `projects list`
- `--agent --help` JSON introspection at every command level
- `--format json` (default for non-TTY) and `--format markdown` (`-m`) output
- A Fera skill (`SKILL.md`) modelled on basecamp-cli's pattern

## Non-Goals (explicit YAGNI)

Write operations, OAuth, Planio-specific extensions, packaging
(brew/deb/rpm), install scripts, completions, rich TUI, MCP-style response
envelope, circuit breakers, jq integration, watch mode, live integration tests.

## Architecture

```
user / agent
    │
    ▼
cobra cmd (e.g. issues list --format json)
    │
    ▼
config (env REDMINE_URL, REDMINE_API_KEY  →  fallback ~/.config/redmine-cli/config.toml)
    │
    ▼
generated client (oapi-codegen, net/http, X-Redmine-API-Key header)
    │
    ▼
output formatter (json | markdown)
    │
    ▼
stdout (clean), stderr (logs/errors)
```

## Key Decisions

- **CLI framework:** Cobra. Tiny, ubiquitous, agent-friendly.
- **API client:** generated by `oapi-codegen` from vendored
  `d-yoshi/redmine-openapi` (pinned commit `b38f1e1b97d231106c055f77eede85a4b636b2ad`).
  Generated code committed to git so a fresh clone builds without `go generate`.
- **Auth:** `X-Redmine-API-Key` header; key resolved from
  `REDMINE_API_KEY` env, then `~/.config/redmine-cli/config.toml`.
- **Output formats:** `--format json` default for non-TTY,
  `--format markdown` (`-m`) human-friendly. No envelope; errors → stderr +
  nonzero exit.
- **`--agent --help`:** returns JSON
  `{command, path, short, long, usage, flags[], subcommands[], notes[]}`.
  Walks the cobra tree; works at every level.
- **Pagination:** `--limit N` (default 25, max 100), `--offset N`,
  `--all` (auto-paginate). `--all` mutually exclusive with `--offset`.
- **Attachments:** download to `os.TempDir()/redmine-cli/<id>-<filename>`,
  print absolute path on stdout. `--out <path>` overrides.
- **Issue detail:** `--include journals,attachments,relations,children`
  → API `?include=`.
- **Config file format:** TOML at `~/.config/redmine-cli/config.toml`:

  ```toml
  url = "https://rm.jkraemer.net"
  api_key = "..."
  default_format = "markdown"
  ```

  Env vars override file values.

## Exit Codes

| Exit | Meaning       | Source                                        |
|------|---------------|-----------------------------------------------|
| 0    | OK            | success                                       |
| 1    | Usage error   | bad flags / missing positional args           |
| 2    | Not found     | 404                                           |
| 3    | Auth error    | 401 / missing config                          |
| 4    | Forbidden     | 403                                           |
| 5    | Rate limit    | 429                                           |
| 6    | Network error | dial / TLS / timeout                          |
| 7    | API error     | other 5xx / unparseable                       |

## Testing Strategy

- Unit tests with `httptest.NewServer` for client behaviour.
- Table-driven tests for output formatters and `--agent --help` JSON shape.
- Cobra command tests run root in-process with captured stdout/stderr.
- Target: ≥80% line coverage on `internal/`. No live API.
- `go test ./...` must be clean.

## Error Handling

- HTTP errors map to exit codes; body truncated to ~512 bytes on stderr.
- Missing config → exit 3 with hint pointing at env vars and config file path.
- 404 → exit 2 with `resource not found: issue 9999`.
- Network errors → exit 6 with underlying error.

## SKILL.md

Lives at `projects/redmine-cli/skills/redmine-cli/SKILL.md`, modelled on
basecamp-cli's skill: triggers, agent invariants, command reference for the
four commands, output guidance, exit codes. Distribution is out of scope —
the skill file ships next to the binary.

## Risks & Open Questions

- d-yoshi spec may not perfectly match Jens' Redmine instance. Mitigation:
  the four endpoints we use (`GET /issues.json`, `GET /issues/{id}.json`,
  `GET /attachments/{id}` + download URL, `GET /projects.json`) are the most
  stable in the API; spec drift unlikely.
- oapi-codegen output for Redmine may have rough edges (e.g. mixed-type
  fields). Mitigation: thin wrapper layer in `internal/client/` if generated
  helpers prove awkward; we do not rely on every generated method.
